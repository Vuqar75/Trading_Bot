# Диагностика почти одинаковых прогнозов ML

В проверенном коде и артефактах ошибки загрузки/экспорта или расчёта признаков
не обнаружено. Сам регрессор сильно сжимает прогнозы к отрицательному среднему
и на сохранённых последовательных проверках не превосходит константную оценку.
Пороги снижать и торговлю включать по результату этого аудита нельзя.

Это аудит после сообщения владельца о 24 планах, вероятностях примерно
21–26.5% и ожидаемом stress-net около −0.31%. Полные исходные векторы именно
этих 24 VM-планов здесь недоступны. Их тождество историческим проверкам не
утверждается; приведённые диапазоны совместимы с установленной моделью.

## Проверенная цепочка

Точный content ID проверенной модели:
`2a0ecbe3351f44f36ce59c336b4e28d089841de21fa5ec915276117fe3d713bc`.
Content ID пересчитан по исходному правилу sorted JSON без model_id; совпал.
Файл LF имеет SHA-256 `3d0d99fe90766a57da48a9f1847dcffb5d330ce1e61260574e0597671fbe1c32`.
Прежний VM byte SHA отличается из-за CRLF; это само по себе не подмена весов.

Входы: 69 515 уникальных ключей symbol/time, 34 float32-признака, без NaN/Inf
в X, с верными side/one-hot asset-полями. Для последней модели воспроизведена
исходная маска May–Oct2026 с purged label_end до 1 ноября: 18 759 строк.
Обучение не запускалось, новые веса не создавались.

1. Все 64 дерева каждой головы проверены на структуру. Массивы восстановлены
   в независимом C-обходчике sklearn без fit. На 2 048 векторах фактический
   portable predictor и C-обходчик дали одинаковые выходы (max error=0).
2. По исходным bootstrap seeds=42 восстановлены веса наблюдений. Сохранённые
   значения всех 1 541 листа классификатора совпали с долей y>0; все 682 листа
   регрессора — со средним исходных stress-target. Max error=0 и 5.86×10⁻¹⁷.
   Это также проверяет знак класса, шкалу target и порядок обучающих строк.
3. По 21 уже имеющемуся архиву, совпавшему с первоначальными SHA-256, построены
   18 фиксированных окон: последний UTC-день May–Oct для BTC/ETH/SOL с 32 днями
   warmup. Сверены истинные 1m OHLCV, runtime-реконструкция 15m и compact X.
   558 случаев (198 BTC,185 ETH,175 SOL), pattern mismatches=0;
   max feature error=1.863×10⁻⁹, ошибка самой агрегации ≤5.33×10⁻¹⁵.
   Это выборочная историческая сверка, не доказательство финальности live REST.

## Почему значения близки

В последней обучающей маске доля положительных stress-исходов — **25.604%**,
средний net одного перекрывающегося контрфактического случая — **−0.306783%**.
Это не доходность счёта и не сумма независимых сделок.

| Признак поведения модели на её обучающей популяции | Значение |
| --- | ---: |
| Центральные 80% P(win), P10–P90 | 20.99–29.69% |
| Центральные 80% expected net, P10–P90 | −0.313228…−0.299584% |
| Средняя доля строк в крупнейшем листе каждого reg-дерева | 90.36% |
| Дисперсия reg-прогнозов / дисперсия target | 0.631% |

Последнее отношение не является R² или оценкой качества на независимой выборке.
У регрессора 618 внутренних разбиений: side не используется ни в одном,
из восьми отдельных pattern-флагов используется только engulf_short, один раз.
Часть направления может косвенно содержаться в остальных признаках; нельзя
на этом основании утверждать, что модель математически не способна различать
все LONG/SHORT. Но ожидаемый net почти не обусловлен явными pattern/side-флагами.
У классификатора такие разбиения присутствуют, его вывод менее сжат.

Числа из отчёта владельца попадают в характерный узкий диапазон этого леса.
Порядок среднего отрицательного target близок к заданным 30 б.п. стрессовых
расходов за круг, но это совпадение не доказывает, что весь убыток вызван только
издержками. Старый OOF-аудит положительного хвоста также показал отрицательный
reference-gross: см. PATTERN_AI_FORECAST_QUALITY.md.

## Сравнение с простым средним без нового обучения

Использованы все 50 628 прежних OOF-прогнозов в 16 временных окнах. Для каждого
окна константы вычислены только по его прежней обучающей маске с label_end
строго до теста: общее среднее и среднее по активу. Перебора параметров нет.

| Метрика, меньше лучше | RF | Константа общая | Константа по активу |
| --- | ---: | ---: | ---: |
| MSE expected net | 0.00006592014 | 0.00006571137 | 0.00006571622 |
| Brier для P(y>0) | 0.19579946 | 0.19770116 | 0.19716259 |

Регрессор хуже общей константы на **0.318%**, поактивной — на 0.310% по MSE.
Классификатор лучше на 0.962% и 0.691% по Brier соответственно. Нельзя выдавать
этот небольшой выигрыш вероятностной метрики за прибыльную торговлю. Target
перекрываются, история уже использовалась проектом; значимость и независимое
подтверждение преимущества не заявляются. Положительный net-tail ранее также
не прошёл проверку, поэтому небольшое улучшение классификации не снимает блокер.

Практический вывод: переустановка того же файла и снижение 60% не устраняют
причину. Следующая обоснованная отдельная гипотеза — направленная нормализация
признаков LONG/SHORT при неизменных временных окнах и издержках, с обязательным
сравнением с обеими константами. Это предложение проверки, не готовая стратегия;
в этом диагностическом этапе она не обучалась и не устанавливалась.

## Исправление доказательности и фактический предел

Старый журнал сохранял из features только ATR, достаточный для уровней, но
недостаточный для повторения ML. Новый writer сохраняет все исходные признаки
и исходные symbol/signal_ms модели для будущих записей. Старые записи
не дополняются догадками и не перезаписываются.
Схема/идентичности/started_ms и расчёт уровней сохраняются; допустимость старых
ATR-only записей сохранена. ML-веса, пороги, GPT-запрос, snapshot_id и бюджет
этой правкой не меняются. Новых экранов/служб/таймеров не добавлено.

`--snapshot-only` у диагностического инструмента воспроизводит сохранённые
выходы по полному вектору, различает WAIT, несовпадение модели, неверные flags,
выход за срок модели и недостаток признаков. Старые ATR-only записи не получают
статус match. Для сверки самих 24 live-векторов нужен их сохранённый полный
снимок; его наличие на VM из cloud не проверялось.

## Воспроизведение и источники

Команда использует локальные файлы, без сети, fit, торгового процесса или бюджета:

```sh
python3 -B tools/audit_pattern_runtime.py \
  --archive-root /path/to/pinned-usdm-data \
  --output /tmp/runtime-diagnostic.json
```

Без --archive-root выполняются forest/OOF проверки без повторной сверки архивов.
Для текущих сохранённых снимков: `--snapshot-only --model MODEL.json
--snapshot technical.json --snapshot technical-ETHUSDT.json ...`.

Источник результата: [runtime_diagnostic.json](research/pattern_ai_results/runtime_diagnostic.json) с
подписями model/NPZ/OOF/summary и 21 архива, окнами, разрезами по активам/месяцам.
Код: [audit_pattern_runtime.py](tools/audit_pattern_runtime.py). Данные: неизменённые model.json,
training_examples.npz, predictions.json.gz, summary.json и sources.json.
Окружение: numpy2.3.5/sklearn1.8.0. Дополнительное обучение/сбор не запускались.
196 адресных тестов прошли с временным HOME, без credentials и IP-сокетов.

VM и её службы из этого чата не менялись. Ранее включённый бесплатный сбор
продолжается по отчёту владельца; паузы и закрытый допуск сохраняются.
Локальная сверка описана в MODEL_RUNTIME_AUDIT_LOCAL_TASK.md.
