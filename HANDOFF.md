# Trading_Bot — контекст передачи работы

## Текущая цель и ограничения

Исходная цель — единый автоматический торговый бот для криптопар: spot,
futures isolated/cross, spot margin с учётом займа, процентов и погашения,
а также другие отдельно согласованные режимы. BTCUSDT — стартовая пара.
Разработка поэтапная: начали со spot, затем добавили симуляцию isolated futures
с плечом 1–10×. Полный набор операций ещё не определён и уточняется по этапам.
Текущая исследовательская задача — проверять стратегии без вмешательства в работающий бот.
Первый этап завершён: расширенный журнал, настраиваемые комиссии/проскальзывание,
offline replay текущей логики и сравнение трёх изменений на раздельных периодах.
Следующий этап пока НЕ согласован для реализации; начать с обсуждения результатов
и выбора следующего исследовательского шага.

Правила пользователя, действующие для следующих этапов:

- Поддерживать этот HANDOFF.md: цель, решения, изменения, проверки, ограничения,
  открытые вопросы и следующий шаг.
- По завершении каждого этапа коммитить код и HANDOFF.md в отдельную исследовательскую
  ветку и отправлять её в GitHub. Сообщать пользователю ветку и хеш коммита.
- Работающий бот НЕ обновлять, не перезапускать и не останавливать без отдельного указания.
- Не читать и не записывать личную конфигурацию Telegram, Telegram ID, токены,
  приватные ключи и другие секреты. Не переносить рабочую базу в Git или тесты.
- Тесты и отдельные временные/in-memory базы разрешены. Новые стратегии не включать.
- Использование реальных средств — только по отдельному разрешению.
- Исключать будущие данные. Параметры выбирать на обучающем периоде, проверять на другом.
- Показывать число закрытых сделок, net PnL, максимальную просадку и долю комиссий;
  явно отмечать недостаточность данных и ограничения модели.

## Предложенная дорожная карта — реализация не разрешена и не начата

Ниже зафиксирован предложенный порядок из облачного чата, а не разрешение на
реализацию, запуск или развёртывание следующего этапа:

1. **Надёжное исполнение и восстановление ордеров.** Неопределённый результат
   отправки, сверка ордеров после сбоев, частичные исполнения, остатки, фактические
   комиссии, защита от повторных Telegram-команд и повторного исполнения.
   Отдельно определить требования к биржевой защите позиции.
2. **Настоящий Futures Testnet isolated.** BTCUSDT, LONG/SHORT, плечо 1–10×,
   фьючерсные данные и биржевые защитные ордера. Текущую симуляцию на спотовых
   ценах не считать реализацией этого этапа.
3. **Общий контроль риска счёта.** Согласовать ограничения на уровне всего счёта,
   а не только отдельной позиции; конкретный набор операций и лимитов уточнить.
4. **Cross futures.** Отдельно согласовать модель общей маржи, риски и операции.
5. **Spot margin.** Учесть заём, начисление процентов, погашение и связанные риски;
   полный набор операций определить до реализации.
6. **Несколько пар.** BTCUSDT остаётся стартовой парой. Реальные средства — только
   после отдельного явного разрешения пользователя, не автоматически после Testnet.

Проверка стратегий идёт параллельно: более длинные данные реального публичного
рынка и последовательные out-of-sample проверки, с явным отделением от Testnet.
Все пять исследованных вариантов пока убыточны на проверочном периоде;
преимущество стратегии не доказано. Добавление рынков и режимов не считается
решением убыточности. Для следующего этапа сначала согласовать объём, операции,
критерии приёмки, ограничения риска и разрешённые среды исполнения.

После каждого завершённого этапа обновлять HANDOFF.md, коммитить код и контекст,

## Что изменено

- `trading_bot/execution.py`: модель paper costs. По умолчанию вход/выход 10/10 bps,
  slippage 0; эти значения воспроизводят прежнюю модель.
- `trading_bot/core.py`: additive `execution_journal`, position_id, quote/fill,
  отдельные комиссии, gross/net PnL, slippage, ограничение убытка маржой, timestamps,
  holding time, причина, SMA/candle snapshot, параметры стратегии/издержек.
  Запись события, баланса, позиции, журнала и уведомления атомарна.
- Настройки `PAPER_ENTRY_FEE_BPS`, `PAPER_EXIT_FEE_BPS`, `PAPER_SLIPPAGE_BPS`
  относятся только к paper futures. Spot/testnet-учёт не заменён этой моделью.
- `trading_bot/replay.py`: offline replay, только in-memory SQLite, fake exchange,
  без Config.load, Telegram, рабочей базы и сетевых запросов/ордеров.
- Варианты: baseline; signed fast-SMA slope; подтверждение следующей закрытой свечой;
  противоположный вход после reversal-close на следующей свече; комбинация трёх.
  В обычный launcher/Telegram эти варианты не подключены.
- `tools/fetch_candles.py`: отдельная публичная загрузка Spot Testnet OHLCV.
- `tools/verify_legacy.py`: сравнение с неизменённым core из Git-коммита `443ca56`.
- `tools/summarize_research.py`: сверка PnL/комиссий/equity/пар позиций и экспорт метрик.

На минуте t доступны только OPEN этой минуты и свечи, закрывшиеся раньше t.

на конечном OPEN с издержками. Обучающее закрытие строго до начала holdout.

Наклон подбирался из 0, 0.5, 1 bps по TRAIN net PnL; tie-break: меньшая просадка,
затем меньший порог. Обе slope-семьи выбрали 1 bps. Общий train-победитель — slope-only.
Все выборы заморожены до holdout. Переизбирать победителя по holdout нельзя.

## Проверки и принятые решения

- В Linux Cloud Shell прошли 64/64 теста. На Windows два старых теста зависят от
  POSIX chmod/особенностей освобождения SQLite; Linux — авторитетный полный прогон.
- Baseline совпал с оригинальным кодом: 772 train- и 572 holdout-события,
  численные расхождения 0; timestamps/direction/quantity/fill/net/reason совпали.
- Изменение будущего OHLC и последующих свечей не меняет результат прошлого.
- Изменение всего holdout не меняет train-метрики, выбор порогов и train-победителя.
- Проверены атомарность журнала, long/short-slippage, cap изолированной маржи,
  legacy-позиции без выдуманных метаданных, сверка баланса/комиссий/просадки.
- Три известные сделки 30 октября дали net -0.114092125013741 USDT,
  комиссии 0.05994585372871497. Это только arithmetic fixtures, не выборка эффективности.
- Все варианты убыточны на обоих периодах. Confirmation лучше на holdout, но не
  выбран постфактум. Opposite увеличил оборот/комиссии и ухудшил результат.
- Никакой кандидат не включён и не рекомендован к включению на основании этого этапа.
- Примерно 22.6 дня искусственного Spot Testnet, один split, аномальные цены,
  отсутствующие funding/стакан/spread/market impact недостаточны для вывода об
  устойчивой эффективности на реальных фьючерсах.

1. Загрузить актуальную удалённую ветку `research/paper-replay-stage1`, прочитать
   AGENTS.md, HANDOFF.md и RESEARCH.md; предварительно сохранить чужие локальные изменения.

3. Для нового согласованного этапа создать отдельную ветку от текущей исследовательской.
4. Восстановить публичный CSV из gzip (см. команду в RESEARCH.md), проверить SHA-256.
5. Выполнить Linux-тесты и при необходимости replay по документированным командам.
   Не запускать `python3 -m trading_bot` или `cloud_shell_start.py` в рамках исследования.
6. Следующий разумный исследовательский шаг для согласования: более длинные данные
   реального публичного рынка с явным отделением от Testnet, несколько последовательных
   out-of-sample периодов, проверка устойчивости к издержкам/режимам рынка. Не менять
   стратегию по единственному holdout и не считать меньший убыток прибыльностью.
7. Завершая этап, обновить HANDOFF.md, коммитить код+контекст в исследовательской ветке,
   push в GitHub без force и сообщить ветку/хеш. Не merge/deploy в рабочий бот без
   отдельного указания. При отсутствии доступа к GitHub честно сообщить блокировку.

Личные настройки и секреты в этом документе отсутствуют и не требуются для replay.
