# Bounded public trade stream install — 15 November 2026

The paper worker uses a pinned websocket-client 1.8.0 (`research/ai_limit_stream_requirements.txt`) and the Binance public USD-M `wss://fstream.binance.com/market/ws/btcusdt@aggTrade` stream. There is no authenticated trade transport. The network thread never opens the ledger. Queue capacity is 32768 events per symbol, writer batches are at most 256, IDs and source ages are checked independently. REST remains for fresh executable book/mark, filters and funding. No aggressive aggregate-trades REST pagination or extra model requests are used.

Faults (disconnect, invalid message, gap, revision, overflow) latch unconfirmed state and suppress execution from that batch. Only financially idle resynchronization may establish a new cursor at a current received stream event; missing historical execution is never backfilled. Under open risk, remaining entry is canceled and quote protection continues. On restart the stream starts unconfirmed. Missing/stale quotes never authorize invented exits. A duplicate is ignored for execution; older/revised duplicate messages conservatively latch unconfirmed state. The last accepted quote is retained if a subsequent REST quote timestamp regresses; its source timestamp and age are preserved and the existing 5-second rule still applies. The discarded/retained times are saved in `bracket_meta.last_quote_regression:BTCUSDT`.

To avoid spending most CPU writing irrelevant ticks during a burst, a complete fresh, contiguous stream batch whose prices all lie within the strict non-crossing entry/target interval is excluded from per-tick financial processing. Its batch hash, cursor and count remain recorded. Any possible entry or target crossing uses the existing per-event financial handler. Quote protection precedes each batch and pulse follows it. Source events are checked again for age at processing. Published state and queue remain bounded; existing service CPU/RAM limits remain in place.

Synthetic prices and temporary ledgers; no real or working paper positions were modified. This is a specified stress case, not a measured Binance network rate. With a 20% CPU and 128MiB memory cgroup, the candidate drained 10000 events in 1.79s, high-water 8720; a separate partial-position/quote-stop-priority test also passed. These tests cover a finite burst, not unlimited sustained arrival above writer capacity. Overflow and lag still block safely.

Final candidate: 107 targeted Linux tests passed, including existing affected protection/financial tests and new queue, ID gap, duplicate, overflow, reconnect latch, stale delivery, partial position, stop priority and quote-regression tests. A pinned maintained WebSocket client handles framing and protocol ping/pong; the application reconnect loop latches uncertainty until safe idle resynchronization. Continuous history cannot be claimed across disconnects. No guaranteed maker fills or profitability are inferred.
