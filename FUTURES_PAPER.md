# Isolated BTCUSDT USD-M futures — paper

Это отдельное приложение, виртуальный счёт, одна LONG или SHORT позиция.
Рыночные данные: публичный Binance USD-M Futures (`https://fapi.binance.com`).
Не использует спотовые цены или Spot Testnet, не читает ключи Binance и не содержит
методов подписи, отправки ордеров, займа или реальной торговли. Это не Futures
Testnet. Cross/margin ещё не реализованы. Прибыльность SMA не доказана.

## Запуск

Linux, Python 3.12+, из отдельного checkout:

```bash
python3 -B -m trading_bot.futures_app --demo
python3 -B -m trading_bot.futures_app --once --db data/futures-paper.db
```

Демо не использует сеть/секреты: SHORT 2×, funding +0.0200, net +0.4002 USDT,
позиция null, свободный баланс 1000.4002. Это арифметический пример, не доходность.
--once получает mark, свечи и оставляет входы на паузе. При ошибке выходит с кодом 1.

```bash
python3 -B -m trading_bot.futures_app --db data/futures-paper.db --telegram
```

Для Telegram — отдельный токен/owner через защищённое окружение
FUTURES_TELEGRAM_BOT_TOKEN и FUTURES_TELEGRAM_OWNER_ID. Не использовать токен
работающего Spot-процесса: два polling-процесса конфликтуют. Существующая личная
конфигурация автоматически не читается. В Git хранить только этот код, не секреты/БД.

Каждый запуск/перезапуск — на паузе. /resume разрешает paper-входы после успешных
проверок. Без Telegram можно запустить с --allow-paper-signal, затем явно передать
SIGUSR1 именно PID этого процесса; запрос обрабатывается после успешного цикла.
Обычный запуск такого обработчика не имеет. SIGINT/SIGTERM завершают процесс.

## Команды

- /status: источник, плечо, маржа, позиция, mark, funding, equity, PnL, просадка.
- /signal: SMA 10/30, сигнал и причина решения. Это не подтверждение ордера.
- /history: последние 10 закрытий, направление, плечо, комиссии, funding, net.
- /pause, /stop: запрещают входы, контроль позиции продолжается.
- /resume: разрешает paper-входы; ошибки данных/блокировка запрещают активацию.
- /close: пауза и запрос закрытия определённой позиции на следующем цикле.
- /leverage 1 … /leverage 10: только на паузе без позиции/запроса закрытия.
- /timeframe 1m|5m|15m|1h: те же условия; выбор сохраняется, signal/candle сбрасываются.

Поддерживается приватный чат владельца. Опасные команды старше старта процесса
или 120 секунд не исполняются. Команда, ответ и offset — один SQLite commit.
Ответ может дублироваться при неопределённой доставке; действие не переисполняется.

## Модель

- Начальный свободный баланс 1000 виртуальных USDT, маржа 10 USDT (CLI --margin,
  >0 и <=10), плечо 1× по умолчанию, isolated без автоматического пополнения.
- Количество = маржа × плечо / модельная цена входа. Количество непрерывное:
  биржевые lot/notional фильтры для настоящих futures здесь НЕ моделируются.
- Fill — mark price с неблагоприятным slippage, default 2 bps на сторону.
  Это приближение, не цена доступного рыночного исполнения/стакана.
- Комиссия default 5 bps на сторону от фактического модельного номинала,
  CLI --fee-bps. Это параметр, не подтверждение тарифов конкретного аккаунта.
- Маржа резервируется из свободного кошелька. Входная комиссия учитывается внутри
  изолированной маржи, выходная — при закрытии. Funding меняет equity позиции.
- Stop 2%, take 4% направленного изменения цены от входа, не проценты маржи.
  Проверка по mark на опросах, по умолчанию каждые 10 секунд плюс сетевые задержки.
- Модельная ликвидация: isolated equity <= 50 bps maintenance от mark-номинала
  + оценка выходной комиссии/slippage. Фиксированный коэффициент (--maintenance-bps),
  не реальные tier/bracket/liquidation-price правила Binance. Нет сбора ликвидации.
- Возврат из позиции не ниже 0; net loss ограничен её маржой. Корректировка cap
  отдельно записана. Это допущение симулятора, не гарантия биржевого isolated.
- Дневной лимит 5 USDT UTC по реализованному net, включая funding при закрытии.
  Это не ограничение открытой просадки и не гарантия потерь <=5 USDT.
- Пауза не выключает mark/funding/risk. Funding загружается до закрытия. При ошибке
  funding/mark цикл останавливается и входы ставятся на паузу: даже защитный выход
  может задержаться. Это только paper, не биржевая защита.
- Обратный crossover закрывает позицию. Противоположный вход не в той же свече:
  со следующей закрытой свечи, если тренд сохранился и входы разрешены. Этот вариант
  не доказан прибыльным; это явное правило нового paper-эксперимента.

## Funding

Читается фактическая опубликованная история /fapi/v1/fundingRate, ограниченная
пагинация, только события после входа и до текущего serverTime. Положительный rate:
LONG платит, SHORT получает; сумма = quantity × markPrice события × rate.
Полная история открытой позиции перечитывается, чтобы поймать позднюю публикацию.
(position_id, fundingTime) дедуплицирует начисление, изменение уже принятого события
вызывает ошибку. Нет выдуманной ставки или предположения о ровно 8-часовом интервале.

API не даёт атомарного снимка: событие, опубликованное после закрытия позиции,
ретроактивно НЕ доначисляется. Это ограничивает точность итогового funding; данные
могут быть исправлены биржей. Это наблюдаемый paper-учёт, не расчёт реального счёта.

## Сохранность и наблюдение

Отдельная SQLite-схема. Spot/legacy БД отвергаются. Перезапуск сохраняет позицию,
плечо и интервал, но включает паузу. Кошелёк, позиция, событие и уведомление меняются
атомарно. flock исключает второй процесс на том же каноническом пути БД.
Финансовые события — futures_events, funding — futures_funding. Equity сохраняется
в метаданных каждый успешный цикл и выборкой в events примерно раз в минуту;
макс. drawdown выборочная, внутритиковые экстремумы не наблюдаются.
Файл futures-health.json содержит время, ошибку, quote, позицию, cash/PnL/equity/DD.
Он не заменяет внешний мониторинг; при падении процесса перестанет обновляться.

```bash
python3 -B -m trading_bot.runtime_backup --schema futures data/futures-paper.db /tmp/futures-backup.db
```

Backup согласованный, integrity_check и atomic replace. Сохранять копии вне диска
для защиты от потери данных. Автоматический backup-таймер Spot для этой БД НЕ подходит.
Пример отдельного systemd-сервиса: deploy/trading-bot-futures-paper.service; он не
установлен и не запущен. Начинает на паузе, без Telegram; допускает ручной SIGUSR1.

## Что проверено и что не запущено

Синтетические данные проверяют математику, funding, восстановление и команды.
Публичный Futures API в текущем облачном executor вернул HTTP 451. --once завершился
ошибкой и сохранил паузу/health. Реальные котировки в этой среде НЕ подтверждены.
Не обходить ограничения, не заменять публичные методы торговыми endpoint.
Проверить --once в Cloud Shell, где Spot API ранее был доступен; доступность Futures
нужно проверить отдельно. Работающий Spot-процесс и его эксперимент не изменялись.
Новый futures-процесс в Cloud Shell не запущен. Платные ресурсы не создавались.
Независимое ревью новой реализации ещё не выполнялось.
