# ИИ-исследование рынка: отдельный наблюдатель

> Локальная проверка 4 ноября 12:34 Баку: публичный срез BTCUSDT/ETHUSDT в WSL успешно собран, 60 закрытых 15m свечей на пару, 20 материалов ФРС и 14 ЕЦБ; отдельного фундаментального набора нет. Локальный `TRADING_BOT_AI` не виден, поэтому API не вызывался и расход не возник. Снимок `2b96cf74fa0a0be5effce8bd7c44ccf36d9b5e50bdb6064cfe97bcdad8102898` и подготовленный запрос хранятся только в игнорируемом research_results; подробности и условия единой budget DB — в HANDOFF.md.

Этап начат 4 ноября 2026 после завершения paper-аудита и объединения PR №1.
Пользователь разрешил технический, фундаментальный и новостной анализ, затем
уточнил: имеющийся API-кредит можно использовать в разумных пределах.
Для первого эксперимента принят консервативный **общий предел $0,25**, а не $0,25
на запуск или день. Автопополнение, расписание и платные поисковые инструменты
не подключены. Сумма $100 на скриншоте не является разрешённым бюджетом.

## Что реализовано

- Отдельные `market_research`, `openai_research`, `research_public_inputs` и
  `research_api_budget`; торговые обработчики не импортируют их. Старый Gemini
  `ai_allows` не изменён, его флаг `AI_ENABLED` не управляет новым наблюдателем.
- Только чтение публичных Spot-свечей BTCUSDT/ETHUSDT; 5m, 15m или 1h.
  Рассчитываются SMA10/30, RSI14 simple, ATR14 simple, изменение за 20 свечей,
  неаннуализированная волатильность лог-доходностей за 20 свечей, объём относительно
  предыдущих 20 свечей и предыдущие экстремумы. Это исследовательские float-метрики,
  а не финансовые проводки. RSI/ATR используют простое среднее, не Wilder smoothing.
- Принимаются только непрерывные свечи с правильными границами. Незакрытая свеча
  исключается, устаревшие данные отклоняются. Получение исторических свечей сегодня
  не разрешает утверждать, что они наблюдались вчера.
- Бесплатные RSS-сводки ФРС и ЕЦБ. Это начальные макроисточники, **не полное
  покрытие криптоновостей**. При недоступном RSS состояние явно сохраняется;
  отсутствие событий не трактуется как отсутствие риска. RSS-текст не равен
  прочитанной полной статье. API-модель сама не просматривает интернет.
- Отдельные новости и фундаментальные материалы с идентификатором, URL,
  издателем, типом источника, временем публикации и первого наблюдения.
  Автосбор токеномики, unlock, on-chain, биржевого стакана и данных деривативов
  пока не реализован; эти материалы можно передать как отдельные наблюдения.
- Строгий JSON-контракт OpenAI Responses: технический комментарий, отдельные
  новостные/фундаментальные гипотезы с ID источников, рыночный режим, качественная
  уверенность, кандидаты стратегий для исследования, риски и ограничения.
  Неизвестные ссылки, лишние поля/торговые команды, отказ и неполный ответ отклоняются.
- Снимок с SHA-256, исходные наблюдения, детерминированный отчёт JSON/Markdown и
  отдельное мнение модели. CLI не открывает торговые БД, не отправляет Telegram,
  не меняет паузы, позиции, защиту и параметры риска.

Структура входа показана в `research/fixtures/ai-observer-synthetic.json`.
**Этот файл содержит вымышленные цены и враждебный тестовый текст, не новости.**
Основные поля: `version`, `as_of_ms`, `captured_at_ms`, `interval`, `markets`,
`news`, `fundamentals`. Свечи имеют Binance-порядок
`[open_ms, open, high, low, close, volume, close_ms]`. Времена — UTC epoch ms.
`source_type=primary` — заявленный тип, а не независимая гарантия достоверности.

## Бесплатная проверка

```bash
python3 -m unittest tests.test_market_research_observer -v
python3 -m tools.market_research \
  --input research/fixtures/ai-observer-synthetic.json \
  --output research_results/ai-offline --prepare-model gpt-6-luna
```

Команда создаёт подкаталог с ID снимка и файлами `input.json`, `snapshot.json`,
`report.json`, `report.md`, `openai-request.json`. Последний только подготовлен:
**никакого API-запроса нет**, даже при установленном OPENAI_API_KEY.

Бесплатное получение текущего среза, когда публичные источники доступны:

```bash
python3 -m tools.market_research --collect-public --interval 15m \
  --output research_results/ai-public
```

Проверки кандидата: **685/685** полного Linux-набора, включая 23 новых теста.

ФРС вернула 20 сводок, ЕЦБ — 14 заголовков без текста статьи.

## Единственный небольшой платный эксперимент

Пользователь создал отдельный restricted-ключ и опубликовал его в настройках
под именем `TRADING_BOT_AI`. Поддерживаются оба имени: `OPENAI_API_KEY`
имеет приоритет, `TRADING_BOT_AI` используется как резервное имя. Значения
не копируются в файлы или тексты команд. Текущий запущенный облачный сеанс ещё
показывает старую версию конфигурации без этой переменной, поэтому живой вызов
здесь **не выполнен**. Нужно применить опубликованную версию к облачному сеансу
или пересоздать его через интерфейс окружения; это не перезапуск торговой VM.
После этого проверить readiness и доступность переменной, не печатая её значение.
Не присылать ключ в чат/GitHub и не добавлять его значение в tracked `.env.example`.
Для ручного запуска можно настроить `OPENAI_API_KEY` в защищённом окружении. Например, в личном
интерактивном Bash-терминале можно ввести ключ без эха и без записи в историю:

```bash
read -r -s -p 'OpenAI API key: ' OPENAI_API_KEY
printf '\n'
export OPENAI_API_KEY
# Выполнить только после настройки ключа и проверки источников/актуальных тарифов:
python3 -m tools.market_research --input research_results/REAL_CAPTURE/input.json \
  --output research_results/ai-public --paid-once \
  --budget-db "$HOME/.local/state/tradingbot-ai/experiment-budget.db"
unset OPENAI_API_KEY
```

`REAL_CAPTURE` заменить на каталог с ID реального среза. Не запускать платный
эксперимент на синтетическом примере. `--paid-once` — отдельное явное включение;
без него нет OpenAI-запросов. После успеха появляется `model-analysis.json`.
Для всех запусков/операторов использовать **тот же единственный budget DB**,
не удалять и не обнулять его. Разные файлы бюджета не имеют общего лимита.

Модель первого экономичного теста — `gpt-6-luna`, без fallback на более дорогую.
Стандартные цены проверены 4 ноября 2026 на официальной странице:
вход $0,10 / выход $0,50 за миллион токенов, скидки кэша не учитываются.
Отправляется `service_tier=default`, `store=false`, максимум 2000 output-токенов;
tools/search и платное хранение не запрашиваются. `store=false` не является
обещанием отсутствия любых служебных логов у провайдера.

Бюджет до HTTP резервирует консервативную оценку: один input-токен на каждый
UTF-8 байт всего тела запроса плюс 4096 на обрамление, output — весь лимит.
Резерв **не возвращается** после таймаута/ошибки/неполного ответа, даже если
реальный расход мог быть меньше. Нет автоматических повторов: запрос с тем же
срезом/контрактом возвращает сохранённый ответ либо сообщает о прежней попытке.
Резервирование сериализуется SQLite до HTTP и переживает перезапуск.
Возвращённые провайдером token usage сохраняются отдельно от резерва.

Это локальный ограничитель по зафиксированным ценам и одному файлу, не банковская
гарантия или лимит всего OpenAI-аккаунта. Перед реальным использованием сверить
тариф и доступность модели; бюджет на панели аккаунта может быть лишь порогом
уведомления. Другие приложения с тем же API-аккаунтом расходуют кредит отдельно.

## Как будем оценивать пользу

Наличие связного текста не доказывает качество анализа. Следующий исследовательский
этап: одинаковые данные и издержки для базовой стратегии, технических правил и
версии с аналитическим фильтром; затем prospective paper-наблюдение. Исторические
мнения современной LLM могут содержать знания о будущем из обучения, даже если
отсечены поздние новости. Поэтому ретроспективный LLM-отчёт не объявлять честным
out-of-sample backtest. Нужен журнал прогнозов до события, затем оценка ошибок,
полноты источников, пропущенных событий, стабильности, стоимости и результатов
после комиссий/funding/процентов. Аналитика не обещает прибыльности.
