# Один фиксированный тест: движение после экстремальной выплаты funding

Зарегистрирован до расчёта. Новая гипотеза, не повтор maker-арифметики или
подгонка отклонённых свечных правил. Общий сохранённый screen показывает:
среди старых stress-групп до4h с break-even>30bps остаются только BTC1h/2h C
с3/1сделками (SHORT/BOTH дублируют путь); этого недостаточно для допуска.
Новые симуляции старых вариантов не нужны.

Гипотеза: высокая уже выплаченная ставка отражает перекос спроса на плечо;
после события возможна обратная ценовая реакция. Это ПРОВЕРЯЕМОЕ предположение,
не установленный прогноз и не ссылка на доказанную прибыль чужой стратегии.
Положительный funding сам по себе не означает перепроданность/перекупленность.

Сигнал: фактический funding-event BTC/ETH/SOL с |rate|>=0.0003 (3bp; фиксированный
порог, не подбирается). После положительного события SHORT, отрицательного LONG.
После указанной ниже поправки время сигнала T равно времени события,
округлённому ВПЕРЁД до1min; вход только minute-open T+1min база /
T+6min стресс. **Выплата события не зачисляется** — позиции в этот момент не было.
Исторические архивы не сохраняют момент фактической публикации rate: эти
задержки являются сценариями, а не доказанной доступностью в реальном времени.

ATR14 Wilder вычисляется по закрытым15m до T включительно, только из имеющихся
свечей; его нормировка — закрытие последней свечи к T. Старый outcome без
изменений: 0.5..2%stop из1.5ATR,2Rtarget,4hmaxпослевхода,stop-first/gap/mark,
fee5bp/side,impact5/10bp и funding только периода открытой позиции.
Использовать неизменный replay() из taker_absorption.py: один отдельный счёт
1000USDT на актив/сценарий, <=100notional,1x,<=5расчётныйриск, cash/step/minimum
proxies без увеличения лимитов. Не открывать позицию ради получения истории.

Данные уже закреплены: Dec2024warmup,Jan2025-Oct2026,70источников
на актив,210 для всех трёх trade/mark/funding, включая supplements. Точный
список сверяется с pattern_ai_results/sources.json. Никаких новых архивов,
сетевых цен, моделей, сервисов, VM/пауза/бюджет/credential-изменений.
Ранее использованная история не является независимой проверкой.

Критерии проверяются ДЛЯ КАЖДОГО актива отдельно, все три раскрываются:
>=30закрытых в каждом сценарии,>=10LONG и10SHORT; положительный base иstress;
положительный stress>=3/4 сегментов2025H1/H2,2026H1/H2; stressбезлучшей>0;
каждый MTMDD<=2%. Это заранее заданный поиск по исходным3активам, не выбор
выигравшей стороны после расчёта. Кандидат при успехе означает только основание
для будущего prospective/risk/execution этапа, не разрешение торговли.
Не менять порог/знак/hold после результата; не делать fallback в momentum.

Проверки: известность rate только после T, точный знак/порог, отсутствие
зачисления выплаты до входа, причинность ATR при усечении будущего, протокол/
source hashes, полный журнал всех сигналов/отказов/исполнений, независимый
fill-PnL/cash/cost/funding/периодный аудит. Reuse уже проверенного исполнения;
без повторного старого обучения или полного набора тестов бота.

## Поправка к точности времени до первого расчёта исходов

Первый запуск0f2b6a7 остановился в проверке timestamp ДО первого исполнения
и результата. Реальный calc_time в архиве бывает, например,1733097600001
(граница+1ms). Требование точного15m-кратного timestamp было ошибочным.
Подлинный event_ms сохраняется, decision T=ceil(event_ms/60000)*60000;
вход=decision+1/6min. При смещении+1ms это вход в+2/+7min от границы,
а не использование уже прошедшего минутного open. ATR включает только
закрытия <=подлинного event_ms, не будущую округлённую минуту.
Изменение опубликовано до первого исхода; знак/порог/риск/stop/target/hold
и данные не менялись. Исходный протокол и abort сохраняются в Git-истории.
