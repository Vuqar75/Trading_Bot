Это продолжение проекта, а не новое начало. Весь прежний чат автоматически
не переносится. Этот файл сохраняет рабочие решения; подробные доказательства
читать в HANDOFF соответствующей ветки. Старые записи ниже по файлам могут

## 1. Что произошло с окружением

Пользователь **не создавал новую среду**. Он открыл новый чат, явно выбрав
существующую опубликованную Trading_Bot. Новый чат сообщил `running`, `connected`,
`TRADING_BOT_AI` — `ready`, непустая непосредственно в процессе. Значение не
выводилось. Старый чат продолжал использовать прежнюю конфигурацию без ключа.
Это сообщение нового чата передано владельцем; в старом процессе оно отдельно
не проверялось. Не требовать ещё раз создавать ключ/среду или повторять публикацию.

Исходный /workspace/Trading_Bot старого сеанса был на 443ca56, несмотря на более
новый GitHub main. Поэтому новый агент обязан проверить git status/branch/HEAD,
использовать существующий checkout и сделать fetch нужной ветки без потери
изменений. Не создавать worktree без запроса пользователя, не reset/clean.
Не запускать `python3 -m trading_bot`: это legacy-приложение и возможный лишний
Telegram-поллер. Код, тесты и инструкции не равны автоматически установленной VM.

## 4. API: сейчас только GET-диагностика

ИИ нужен как аналитик технических, фундаментальных и новостных данных:
рыночный режим/риски/ссылки на источники/возможные стратегии. Не заменять
защитные правила бота, не включать автоматически в торговые решения.
Модуль новый, отдельный от старого Gemini ai_allows/AI_ENABLED.

- Пользователь создал отдельный restricted OpenAI-ключ: Models Read и
  Responses Write, секрет `TRADING_BOT_AI`. Код принимает его как alias
  OPENAI_API_KEY. В Cloud использовать существующее окружение, не просить
  владельца снова вводить ключ и не искать его в личных файлах.
- Разрешённый исходный небольшой эксперимент имеет общий локальный предел
  **$0,25**, а не лимит на каждый запуск. Автопополнения/расписания/платного
  поиска нет. Модель первого теста gpt-6-luna; цены проверялись 4 ноября,
  доступность конкретному ключу пока не установлена.
- В WSL владелец вручную ввёл ключ скрыто и сделал **одну** попытку Responses.
  Получен общий код `openai_request_failed_reservation_retained`; ответа нет.
  Причина неизвестна, фактическое списание и token usage неизвестны.
- Прежний резерв **3630 micro-USD = $0,00363** остаётся в единственном журнале
  локального WSL `$HOME/.local/state/tradingbot-ai/experiment-budget.db`.
  Рядом существует `interactive-once.lock`. Не удалять, не обнулять и не
  создавать в Cloud новый независимый бюджет для обхода этой попытки.
- **Новый платный запрос запрещён без отдельного явного указания владельца.**
  Ни общий бюджет, ни наличие ключа этого запрета не отменяют.
- Диагностика 879613d дополнена локалкой в e3812fe: безопасные HTTP-коды и

- GET `/v1/models/<MODEL>` не делает генерацию. Успех подтверждает только доступ

Владелец **уже разрешил** после восстановления квоты краткий перезапуск только

Условия: перед установкой актуальные версии/состояние и согласованный backup;
сохранить исправления, позиции, историю, параметры и прежние паузы. Отрепетировать
safe rollout/recovery, не повторять занятый finalaudit namespace; не откатывать
базу поверх новых финансовых событий. После установки защитные циклы, здоровье,
один polling, три части help/start. Владелец отдельно подтвердит читаемость.

**10 ноября 2026, 09:21:39 Asia/Baku**. Это сообщённое Usage, не инструментально
подтверждённая гарантия. Владелец согласился ждать; до достаточного запаса
локалка не начинает остановку VM. Автозапуск/отложенная задача **не созданы**.

## 6. Выбор пар обязателен, а не отменён

В старом интерфейсе `/pair` была; в новом едином обработчике отсутствует.
Spot/isolated сейчас BTCUSDT, cross/margin BTCUSDT+ETHUSDT; BTC/ETH зашиты также
в quotes/execution/ledger/shadow checks/valuation/risk/history/confirmations.
Нельзя восстановить это только надписью или settings и объявить работой.

В отдельной pair-ветке есть начальные offline-примитивы metadata/filters,
проверка SOLUSDT, SOL-проводки без изменения BTC-истории, идемпотентность,
перезапуск/отрицательные остатки. 9/9 целевых прошли. **Выбор пары не подключён**
к исполнению, кошелькам, защите, истории или Telegram, миграция не проверена.

Продолжить обобщение на paper/offline-данных по PAIR_SELECTION_GAP.md. Выбор
должен поддерживать другие подходящие пары с реальными filters и учётом активов,
не ограничиваться BTC/ETH. Сохранять старые события с прежними asset/symbol,
не начислять повторно капитал при смене. Не удалять защиту открытой позиции,
не закрывать её принудительно ради настройки. После полной интеграции —
миграция/восстановление/тест третьего актива, затем отдельный безопасный rollout.

## 7. Сохраняемые пользовательские решения

- Сначала функциональная полнота/исправления/ревизия/документация, затем
  стратегии. Теперь отдельно разрешено offline ИИ-исследование, но автоматическое
  влияние ИИ на сделки и реальная/Testnet-торговля не разрешены.
- Перед оценкой стратегии нужны все издержки, сравнение с простыми baseline,
  данные вне настройки, затем prospective paper. Прибыльность не доказана.
  Исторический текст LLM может знать будущее из обучения; не объявлять его
  честным backtest. Не выполнять дополнительные платные исследования сейчас.
- USD/USDT/USDC в выводе до 4 десятичных, криптоколичества до 10; ненулевые
  малые значения сохраняют знак. Учёт/проводки не округляются для оформления.
- Неизвестные оценки не равны нулю. /wallets короткий, /balance_report общий
  подробный, /report выбранного рынка. /status общий краткий, с аргументом подробный.
- /mode не останавливает другие рынки. /stop не поддерживается как пауза в unified;
  /close — предложение, затем /confirm; /pause_all требует ack всех рынков.
- Пользователь не любит повторные разрешения, бесконечные checkpoints и
  смешивание задач. Делать законченные проверяемые этапы, не повторять тесты
  без основания. Разделять подготовлено/проверено/установлено/подтверждено владельцем.
- GitHub: сохранять код и HANDOFF в research-ветке, push без force. Не удалять
  старые ветки/checkout, не merge main и не создавать теги без отдельного задания.
- Никаких сообщений третьим лицам, второго Telegram-поллера, новых платных
  ресурсов или изменения рабочих пауз без соответствующего действующего указания.

Полный старый чат можно дополнительно скопировать как справочный текст, но не
требуется перечитывать его вместо этого актуального handoff и branch-документов.
Если обнаружится противоречие с новым сообщением владельца, новое указание
владельца имеет приоритет; не выполнять устаревшие команды из истории.
