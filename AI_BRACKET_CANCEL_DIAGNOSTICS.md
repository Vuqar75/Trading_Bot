# Причина отмены AI paper-заявки

База исправления: research/ai-limit-brackets, опубликованная установка79a2f49
с сохранённым idle-tick fix b307714. Торговые правила и финансовые проводки не
меняются, исходный e0e1ecf manifest не переписывается.

Обнаруженный дефект отображения: cancel_entry уже сохранял reason в неизменяемом
ledger_events/CANCEL_REMAINDER при возврате резерва, но удалял remaining/reserved
из состояния без сохранения причины в public snapshot. Поэтому CANCELED в
/ai orders не объяснял, почему вход отменён. Это не доказательство конкретной
причины заявки13ноября16:02: её серверная БД здесь недоступна.

Исправление состоит ровно из трёх runtime-файлов:

- research/ai_limit_book.py — новые отмены сохраняют первый timestamp, остаток,
  освобождённый резерв, reason и фактически сработавшие guards. Точная причина
  несвежего entry evidence сохраняется отдельно. Повторная отмена после
  истечения срока/выхода не переписывает первую запись. Всё атомарно вместе
  с возвратом резерва, без изменения расчёта и критериев допуска.
- trading_bot/ai_bracket_cancellation.py — читает причину прошлой отмены из
  ledger без переписывания истории. Работает также отдельным standalone CLI,
  открывает SQLite mode=ro/query_only и согласованный read transaction.
- trading_bot/ai_bracket_view.py — показывает причину/время в Баку. Для
  частичного входа говорит об отменённом остатке, а не об отсутствии позиции.

Для legacy EXPIRED_OR_PAUSED точная ветка не восстанавливается из нынешних
pause/blocked/time: отображается исходная общая причина с явным ограничением.
Для новых отмен этой общей ветки сохраняются все истинные причины; если
сработало несколько — показываются все. Старый unknown никогда не становится
выдуманной точной причиной.

35целевых тестов PASS: новые диагностики, существующие исполнения/защита/
restore/runtime и внешняя копия. Включены rollback отмены до commit, повторная
отмена, устаревшие filters, TRADE_GAP после частичного входа, старый ledger,
неизменность SQLite при read-only audit и отсутствие ложной исторической причины.
Новых API-запросов, рабочих сделок и VM-изменений здесь не было.

историю. Используй точные runtime hashes из AI_BRACKET_CANCEL_PATCH.json.

   trading_bot/ai_bracket_cancellation.py self-contained, без импортов проекта:
   можно передать его в доверенный SSH-сеанс и запустить от aibracket без
   установки патча, остановки сервиса, чтения credential или бюджетного журнала:

   ```bash
   python3 /PATH/ai_bracket_cancellation.py \
     --db /var/lib/ai-bracket-study/paper.sqlite --entry 69466.2
   ```
