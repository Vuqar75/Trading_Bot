# Нелинейная модель на тех же технических и макроданных

Исходный Ridge из `8ce782c` сформировал один или два входа. Проверяем, меняет ли нелинейное взаимодействие признаков экономический результат. Данные, общая выборка, разделение по времени, цели обучения, порог +5 б.п., расходы, риск, исполнение и критерии допуска сохраняются из AI_TECHNICAL_MACRO_PROTOCOL.md. Период январь–октябрь 2026 уже известен проекту и используется для сопоставимости.

Заменяем Ridge парой HistGradientBoostingRegressor для LONG и SHORT с параметрами из предыдущего panel_net_ml: max_iter=100, learning_rate=0.05, max_leaf_nodes=7, max_depth=3, min_samples_leaf=200, l2_regularization=10, early_stopping=False, random_state=20261112. Считаем на одном CPU-потоке. У дерева стандартизация не используется. Оцениваем те же три набора признаков. Контрольная версия Ridge заморожена, настройки после расчёта не меняются.

Перед интерпретацией проверяем совпадение времён, наблюдений и сделок простого правила с сохранённым контролем. Отчёт показывает последовательные счета, вклад каждого набора, результат без лучшей сделки и качество ранжирования. Дополнительно считаем разницу недельных парных результатов между полными моделями. Отчёт показывает оба полугодовых отрезка. Допуск требует выполнения исходных ворот и преимущества полного нелинейного варианта перед полным Ridge после стрессовых расходов. Новая ценовая история для независимого допуска потребуется отдельно. Расчёт offline.
