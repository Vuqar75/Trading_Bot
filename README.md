# Trading_Bot — paper на VM

Обновлено 4 ноября 2026. Экспериментальная автоматическая торговля виртуальными средствами: Spot, USD-M futures isolated и cross, Spot margin cross. На VM работает код `29d1fc6061902b00c49739b4b74c2f6285a15a3d`; исследовательская ветка может быть новее. Binance/Testnet-ордера и реальные средства не разрешены текущим заданием. Рабочие параметры, позиция и состояние паузы определяются фактическим состоянием, а не этим документом.

Один Telegram-поллер управляет четырьмя отдельными процессами; переключение режима не останавливает другие рынки. Общий авторитетный журнал — `/var/lib/tradingbot/paper-financial/shared-paper.db`, очередь команд и observation находятся в `/var/lib/tradingbot/Trading_Bot_paper_state/`. Переводы — только виртуальные, между активными кошельками, с проверкой свободных средств и паузы. Резерв ордера и обеспечение не становятся доступными для перевода только потому, что где-то отображается свободный остаток.

| Команда | Назначение |
| --- | --- |
| `/mode [spot\|futures\|futures_cross\|margin_cross]` | Выбор рынка; `futures` — isolated. |
| `/status [spot\|futures\|futures_cross\|margin_cross]` | Сводка всех или подробности рынка. |
| `/signal`, `/history`, `/report` | Сигнал, сделки и результаты выбранного рынка; `/report` содержит день Баку и накопительный итог. |
| `/pause`, `/resume`, `/pause_all` | Остановка/разрешение входов выбранного рынка или пауза всех; управление открытым риском продолжается при доступных данных. |
| `/timeframe`, `/leverage` | Показ и выбор параметра при разрешённых условиях; плечо 1–10× для futures и 1–3× для margin. |
| `/close`, `/confirm ID`, `/cancel ID` | Предложение конкретного закрытия и подтверждение/отмена; автоматическая защита не требует ручного подтверждения. |
| `/wallets`, `/wallet ИМЯ`, `/transfer ИСТОЧНИК ПОЛУЧАТЕЛЬ СУММА`, `/transfers` | Кошельки и подтверждаемые виртуальные переводы. |
| `/balance_report [today\|all]` | Общая оценка и сверка средств; это отдельный от торгового `/report` отчёт. |
| `/loans`, `/interest`, `/repay ID_займа КОЛИЧЕСТВО` | Заём, проценты и предложение погашения в режиме margin cross. |
| `/help` | Справка с выбранным рынком. |

`/confirm` и `/cancel` применяются к конкретным предложениям; учитываются срок и состояние. Наличие команды не означает, что её действие безопасно при ошибке или блокировке. Неизвестные расходы и неполные котировки не равны нулю. Финансовые величины и PnL модельные; комиссия, funding, проценты и ликвидация не гарантируют совпадения с биржей. Окончательность публикации funding источником не гарантируется. Стратегии остаются исследовательскими, прибыльность не доказана.

Эксплуатация и восстановление: [инструкции VM](VM_PAPER_OPERATIONS_2026_11_01.md), [внешние копии и email](EXTERNAL_BACKUP_EMAIL_RUNBOOK.md), [финансовые определения](PAPER_FINANCIAL_DEFINITIONS.md), [HANDOFF](HANDOFF.md), [ROADMAP](ROADMAP.md). Копии проверять на отдельной среде без торговли и второго поллера; старой базой нельзя перезаписывать новые финансовые события. Изменения VM выполняются только в пределах действующего указания владельца. Состояние итоговой проверки: [FINAL_AUDIT.md](FINAL_AUDIT.md).

# Торговый бот: экспериментальная первая версия

Изолированное исследование paper futures: см. [RESEARCH.md](RESEARCH.md).
Новые варианты стратегии доступны только в offline replay, не в работающем боте.

Python 3.12+, стандартная библиотека, SQLite. Платные сервисы и Python-пакеты не нужны.
Реальная торговля отключена. По умолчанию `paper`: виртуальные сделки по котировкам Binance Spot Testnet.
Режим `testnet` отправляет ордера только на `testnet.binance.vision`, с отдельными тестовыми ключами.
Котировки тестовой среды могут отличаться от реального рынка.

## Запуск

Из существующего checkout, без создания дополнительных worktree:

```bash
cd /workspace/Trading_Bot
python3 -m unittest discover -s tests -v
cp .env.example .env
# Заполните .env локально; не публикуйте его и не отправляйте ключи в чат.
set -a
. ./.env
set +a
python3 -m trading_bot
```

Бот начинает на паузе. Для Telegram нужны `TELEGRAM_BOT_TOKEN` от BotFather и
`TELEGRAM_OWNER_ID` — числовой ID вашего Telegram, не UID Binance.
При отсутствии Telegram разрешение входов недоступно: бот только получает котировки.
Команды: `/help`, `/status`, `/resume`, `/pause`, `/stop`, `/close`, `/pair BTCUSDT`, `/mode`.
`/history` показывает последние 10 покупок и продаж из текущей базы, с расчётным результатом продаж.
`/signal` показывает последнее сохранённое решение стратегии: источник Binance Spot Testnet,
таймфрейм 1m, начало и границу закрытия свечи, предыдущие и текущие SMA 10/30,
BUY/SELL/HOLD и причину входа, выхода или пропуска. Команда не запрашивает новые свечи
и не размещает ордер. Отображается последнее решение, а не полный архив всех проверок.
При повторном опросе той же свечи сохраняется исходная причина: включение /resume
после пропущенного на паузе пересечения не вызывает вход задним числом.
При защитном выходе средние не рассчитываются; при сбое отображается тип ошибки.
Данные Testnet могут отличаться от графика основного Binance; сравнивать нужно один источник.
`/status` показывает последнюю полученную котировку, её возраст и последнюю зарегистрированную ошибку.
Время сообщений и истории — Баку (UTC+4); дневной лимит по-прежнему считается по UTC.
Котировка помечается устаревшей, если её возраст больше 120 секунд или двух интервалов опроса.
Время котировки означает время получения HTTP-ответа, а не время последней сделки на бирже.

Покупки, продажи и ошибки автоматически отправляются владельцу в Telegram.
Очередь хранится в SQLite: сбой доставки не отменяет записанную сделку, отправка повторяется позже.
При неоднозначном подтверждении Telegram возможен повтор сообщения; ордер из-за этого не повторяется.
Одинаковая ошибка одного компонента уведомляет не чаще раза в 15 минут.
Ошибка торговли запрещает новые входы; контроль существующей позиции повторяется.
Последняя ошибка в статусе сохраняется как история и не означает, что сбой всё ещё продолжается.
При обновлении старая база дополняется таблицей очереди, старые сделки повторно не рассылаются.
`/stop` запрещает новые входы, но НЕ закрывает позицию; `/close` закрывает её и включает паузу.
При перезапуске сохраняются позиция, пауза и выбранная пара. Один процесс на базу.

Для ордеров Testnet: `BOT_MODE=testnet`, отдельный `DB_PATH=data/testnet.db`,
ключи `BINANCE_API_KEY` и `BINANCE_API_SECRET` именно Spot Testnet.
Доступ к аккаунту проверяется при запуске. Используйте отдельный тестовый аккаунт без ручных сделок.
Реальные фьючерсы, их Testnet API и маржинальный спот пока не подключены.

## Симуляция фьючерсов LONG/SHORT

В режиме `paper` отправьте `/mode futures`, затем `/leverage 1` ... `/leverage 10`.
Шаг плеча — 1, начальное значение — 1×. `/mode spot` возвращает спот.
Смена рынка/плеча запрещена с открытой позицией или pending и включает паузу.
Плечо и рынок сохраняются в базе; Cloud Shell launcher включает паузу при каждом запуске.
Новые настройки не меняют существующую спотовую позицию и историю.

Это локальная модель линейного USDT-контракта на СПОТОВЫХ ценах Binance Testnet.
Фьючерсных котировок, mark price, funding, биржевых ордеров здесь нет.
Источник явно показан в `/status` и `/signal`. Режим `testnet` остаётся только спотовым.

`TRADE_USDT` в этом режиме задаёт изолированную маржу (по умолчанию 10 USDT),
а размер позиции = маржа × плечо. Начальный свободный виртуальный баланс — 1000 USDT,
при открытии резервируется маржа, при закрытии возвращается её остаток с результатом.
Комиссия модели — 0,1% номинала на входе и выходе; обе учитываются при закрытии.
Ставка условная, не тариф Binance. Например, 10 USDT × 10 = 100 USDT позиции.
LONG приносит прибыль при росте, SHORT — при падении. Одновременно одна позиция.

Пересечение вверх открывает LONG, вниз — SHORT. Обратное пересечение закрывает
открытую позицию; мгновенного переворота нет, новый вход — по следующему пересечению.
Пауза блокирует только входы; `/close` закрывает любое направление и включает паузу.
`/history` объединяет спот и фьючерсы с отметками OPEN/CLOSE LONG/SHORT и плечом.
Дневной лимит суммирует реализованный результат обоих рынков в текущей базе.

Стоп 2% и тейк 4% заданы по движению ЦЕНЫ, не доходности маржи.
При 10× стоп 2% соответствует примерно 20% маржи плюс комиссии.
Проверка раз в минуту не гарантирует исполнение по порогу. При гэпе потери могут быть больше.
Модельная ликвидация проверяется раньше стопа: остаток маржи после входной комиссии
и PnL сравнивается с 0,5% текущего номинала плюс 0,1% комиссии выхода.
Это упрощённый порог, не точная ликвидационная цена Binance и не её таблица risk tiers.
При закрытии/ликвидации возврат маржи ограничен снизу нулём, потери — выделенной маржой;
остальной виртуальный баланс не списывается. Отдельного сбора за ликвидацию нет.
Funding, проскальзывание и внутриминутный путь цены не моделируются.

## Стратегия и ограничения

Пересечение простых средних 10/30 по закрытым минутным свечам. Одна длинная позиция,
размер покупки по умолчанию 10 USDT. Выход при обратном пересечении, убытке 2% или прибыли 4%.
Лимит реализованного чистого убытка за UTC-день — 5 USDT; он запрещает новые входы.
Это не лимит просадки открытой позиции. В paper учитывается комиссия 0,1% на сторону,
но нет модели проскальзывания. Для Testnet PnL также приблизительный.

Стопы программные, проверяются раз в `POLL_SECONDS` (60 секунд по умолчанию).
При отключении сервера/сети защита не работает. Биржевые защитные ордера ещё нужны.
При неоднозначном результате отправки или частичном исполнении сохраняется `pending`:
торговля блокируется. Автоматическая сверка, обработка остатка и восстановление таких ордеров
ещё не реализованы. Не удаляйте pending вслепую: сначала сверяйте ордер по client_id,
баланс и исполнения на Testnet. Без этого режима live не будет.

## Gemini — необязательный эксперимент

`AI_ENABLED=true`, `GEMINI_API_KEY`, `GEMINI_MODEL` (доступная вам модель).
ИИ вызывается только перед входом (BUY на споте, LONG/SHORT в симуляции фьючерсов);
передаются направление, тип симуляции, символ и цены, без данных аккаунта.
При ошибке, отсутствии ключа или некорректном ответе вход отклоняется.
ИИ не отменяет лимиты и выходы. При отключённом ИИ работает базовая стратегия.
Результативность фильтра не проверена. Сравнение на истории, комиссии и проскальзывание — следующий этап.
Условия и квоты Gemini проверяйте в своём аккаунте, бесплатность не гарантируется.

## Облако

Для постоянной работы нужен VPS. Cloud Shell подходит для разработки, но не работы 24/7.
Dockerfile подготовлен; сборка и облачный запуск требуют отдельной проверки:

```bash
docker build -t trading-bot .
docker volume create trading-bot-data
docker run -d --name trading-bot --restart unless-stopped --env-file .env \
  -v trading-bot-data:/app/data trading-bot
docker logs --tail 50 trading-bot
```

Храните резервные копии SQLite (через SQLite backup API) вне сервера, секреты отдельно от кода.
Не запускайте два экземпляра с одним аккаунтом. Нужны исходящие HTTPS-соединения к
`testnet.binance.vision`, `api.telegram.org` и, если включён ИИ, `generativelanguage.googleapis.com`.
Ключи Binance для подписания запросов должны быть настоящими значениями в процессе:
proxy-placeholder не подходит для локальной HMAC-подписи.
