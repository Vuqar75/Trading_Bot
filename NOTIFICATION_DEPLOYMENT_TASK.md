# Локальному Codex: установка уведомлений (разрешена пользователем)

Пользователь явно попросил обновить работающего бота. Здесь подготовлен код, но
нет gcloud/аутентифицированного SSH к его Cloud Shell. Установка ещё НЕ выполнена.
Ветка research/trade-notifications основана на 5a62e41abb7f5085c69a63ceb7cf998871cf53ee.

Выполни установку до результата, не заканчивай только планом:

1. Подключись имеющимся доверенным gcloud SSH. Прочитай HANDOFF.md и
   DEPLOYMENT_2026_11_01.md. Зафиксируй состояние обоих процессов, открытые позиции,
   паузу, блокировки, незавершённые ордера, версии кода. Секреты не показывать.
2. Получи эту ветку в отдельный checkout и запусти полный Linux-набор (240 тестов).
   Сохрани чужие локальные изменения при наличии, не перезаписывай их.
3. Поставь входы обоих paper-приложений на паузу, корректно останови оба торговых
   процесса, не закрывая позиции. Сделай согласованные backup обеих баз и integrity
   check. Монитор/backup loops не должны быть ошибочно приняты за торговые процессы.
4. Обнови код обоих checkout до точного HEAD этой ветки. Базы, позиции, история,
   выбранные интервалы, плечо, маржа и издержки остаются прежними; БД не обнулять.
5. Запусти futures без Telegram через прежнюю команду, на паузе. Spot запусти через
   прежний защищённый launcher с переменной FUTURES_OUTBOX_DB, указывающей на
   ~/Trading_Bot_futures_state/futures-paper.db. Пример внутренней команды tmux:

   exec env FUTURES_OUTBOX_DB="$HOME/Trading_Bot_futures_state/futures-paper.db" python3 -B deploy/cloud_paper_launch.py >> "$HOME/Trading_Bot_paper_state/runtime.log" 2>&1

   Команду выполнять из ~/Trading_Bot_paper_observation. Использовать только один
   polling-процесс; relay читает/подтверждает futures outbox, не polls Telegram.
   FUTURES_OUTBOX_DB — путь, не секрет. Токен использует прежний protected launcher.
6. Проверь свежий health, сохранность позиций, один Spot-поллер, один futures worker,
   блокировку второго отправителя futures outbox и отсутствие ошибок SQLite.
   Relay отдельной CLI-командой не запускать: он встроен в Spot-процесс.
7. Сформируй по одному примеру открытия и закрытия Spot и futures на временных БД.
   Доставь владельцу с явной пометкой «ПРИМЕР ФОРМАТА — НЕ РЕАЛЬНАЯ СДЕЛКА», через
   разрешённый существующий send API без второго getUpdates/polling и без изменения
   рабочих позиций. Проверь API-ack. Не фабрикуй рабочие события и не заявляй получение
   владельцем без его подтверждения. Старые сообщения в outbox не переформатируются.
8. Если прежние входы были разрешены, после успешного health/сверки разрешено явно
   восстановить их SIGUSR1. Ручную паузу не отменять. При ошибках/блокировке не resume.
9. Проверь мониторы/резервные копии после разрыва SSH, запиши технический перерыв.
   Обнови HANDOFF.md и эксплуатационные команды с FUTURES_OUTBOX_DB, коммит/push.
   Сообщи фактические версии/процессы/паузы и подтверждённые API отправки сообщений.

Никаких реальных или Testnet-ордеров, платных ресурсов, изменения параметров стратегии
или второго polling с тем же токеном. Futures команды в этом Telegram по-прежнему
НЕ обрабатываются: входящие команды относятся к Spot; relay — только уведомления.
Остановка Cloud Shell остановит оба приложения и доставку. Если Spot-процесс упадёт,
futures продолжит писать в свой outbox; доставка возобновится после запуска Spot.
